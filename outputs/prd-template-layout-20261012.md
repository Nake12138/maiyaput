## 一、背景与现状问题

海外投放系统「TT 批量投放 → 模板管理」页面当前将所有模板类型平铺为一级页签，共 6 个：账户包、文案模板、定向包、充值模板、回传模板、TikTok 账号包。

**存在问题：**

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| P1 | 一级页签数量多达 6 个，视觉冗余、识别成本高 | 用户查找模板时认知负担重 |
| P2 | 「文案模板 / 充值模板 / 回传模板」同属**配置型模板**，与「账户包 / 定向包 / TikTok 账号包」等**账号/定向组合型模板**业务属性不同，却被同等平铺展示 | 模板类型无分层，结构松散 |
| P3 | 一级页签过多导致扩展性差：后续新增配置型模板（如出价模板、预算模板）时需再次扩容一级页签 | 长期演进成本高 |

---

## 二、目标与预期收益

1. 一级页签由 6 个精简为 4 个：**模板管理、账户包、定向包、TikTok 账号包**。
2. 将同属配置型的 **文案模板、充值模板、回传模板** 收敛到「模板管理」下的**二级子页签**，形成一级 + 二级的层级结构。
3. 保持「账户包、定向包、TikTok 账号包」仍为一级页签，位置与交互不变。
4. 数据源、字段、接口、抽屉/弹框交互均**不调整**，仅做页面布局层级归集。

**预期收益：**

- **结构清晰**：同类型模板聚合，一级页签减半，降低认知成本。
- **扩展友好**：后续新增配置型模板可直接放入「模板管理」二级页签，不影响一级页签。
- **交互统一**：配置型模板共用「模板管理」容器，统一查询、重置、新增等操作位置。

---

## 三、需求范围

- 「模板管理」下新增二级子页签：**文案模板、充值模板、回传模板**，默认进入「模板管理 → 文案模板」
- 一级页签精简为：模板管理、账户包、定向包、TikTok 账号包
- 子页签切换、默认选中、状态保持（URL hash / localStorage）
- 面包屑保持「首页 / 批量投放 / 模板管理」

## 四、功能需求详述

### 4.1 模板管理页面页签结构调整

| 编号 | 规则 |
| --- | --- |
| R1-1 | 一级页签仅保留 4 个：模板管理、账户包、定向包、TikTok 账号包 |
| R1-2 | 默认进入「模板管理」一级页签，并展开二级子页签 |
| R1-3 | 「模板管理」下二级子页签为：文案模板、充值模板、回传模板（默认选中「文案模板」） |
| R1-4 | 一级页签切换时，下方内容区域整体替换为对应页签内容；二级子页签切换时仅替换列表区域，不重置面包屑和页面标题 |
| R1-5 | 面包屑始终为：首页 / 批量投放 / 模板管理（不显示子页签名） |
| R1-6 | 子页签状态通过 URL hash（如 `#/template/copy`）或 localStorage 持久化，刷新页面后恢复当前所在子页签 |
| R1-7 | 文案模板、充值模板、回传模板不再作为一级页签出现；旧入口若被外部系统调用，通过前端路由重定向到新路径 |

### 4.2 「账户包 / 定向包 / TikTok 账号包」交互保持不变

| 编号 | 规则 |
| --- | --- |
| R2-1 | 「账户包 / 定向包 / TikTok 账号包」三个一级页签的入口路径、面包屑、页面标题保持原样 |
| R2-2 | 三个页签内部的搜索条件、表格列、分页、新增/编辑/复制/删除抽屉与调整前完全一致 |
| R2-3 | 三个页签的数据源、接口、权限控制保持现状 |

### 4.3 二级子页签：文案模板

| 编号 | 规则 |
| --- | --- |
| R3-1 | 文案模板相关功能（列表、筛选、新增/编辑弹框、批量操作等）从原一级页签完整迁移至「模板管理 → 文案模板」下，功能不变 |
| R3-2 | 新增文案按钮位置与原位置一致 |
| R3-3 | 表格工具条（已选数量、批量删除、列设置、全屏）保持可用 |

### 4.4 二级子页签：充值模板

| 编号 | 规则 |
| --- | --- |
| R4-1 | 充值模板相关功能（列表、筛选、新增/编辑抽屉等）从原一级页签完整迁移至「模板管理 → 充值模板」下，功能不变 |
| R4-2 | 充值档位相关表单字段与交互保持原样 |

### 4.5 二级子页签：回传模板

| 编号 | 规则 |
| --- | --- |
| R5-1 | 回传模板相关功能（列表、筛选、新增/编辑抽屉等）从原一级页签完整迁移至「模板管理 → 回传模板」下，功能不变 |
| R5-2 | 回传事件勾选、回传地址输入等表单交互保持原样 |

### 4.6 视觉与交互规范

| 编号 | 规则 |
| --- | --- |
| R6-1 | 一级页签沿用当前 `.tabs` 样式，高度、字体、间距保持不变 |
| R6-2 | 二级子页签使用 `.tpl-subtabs` 样式（沿用原型中已有的二级页签视觉） |
| R6-3 | 二级子页签位于一级页签下方、筛选条件上方，与列表区域保持 16px 间距 |
| R6-4 | 子页签切换为客户端渲染，不重新加载整页；列表数据按需请求 |
| R6-5 | 子页签按钮保留 `aria-selected` 与键盘聚焦态 |

## 五、交互细节与边界

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| E1 | 首次进入模板管理页面 | 默认选中「模板管理」一级页签 → 「文案模板」二级子页签，展示文案模板列表 |
| E2 | 用户在「模板管理」下切换子页签 | 仅替换列表区域，面包屑保持「首页 / 批量投放 / 模板管理」 |
| E3 | 页面刷新 | 通过 URL hash 或 localStorage 恢复上次所在的一级页签与二级子页签 |
| E4 | 旧入口（指向文案/充值/回传作为一级页签）被调用 | 前端路由重定向到「模板管理 → 对应子页签」 |
| E5 | 切换到「账户包 / 定向包 / TikTok 账号包」 | 内容区整体替换，列表/筛选/抽屉与原版完全一致 |
| E6 | 后续新增配置型模板（如出价模板） | 直接作为「模板管理」下的新二级子页签接入，一级页签不需调整 |
| E7 | 子页签状态丢失（localStorage 被清除） | 默认回到「文案模板」子页签，不报错 |

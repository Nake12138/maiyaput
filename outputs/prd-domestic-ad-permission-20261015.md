## 一、背景与现状问题

投放业务采用**排班制**：同一投放小组按时间分班值守，同一批广告数据在不同时段由不同用户负责跟进。业务上典型场景是——组员休息或临时不在时，由组长（或同组当班用户）代为调整组员名下广告，包括启停、改预算、重试失败任务等。

**当前权限模型**：数据结构上已归属到具体创建人，列表按数据范围（用户 / 团队）可查看，但**操作入口只对创建人开放**。这导致"看得见但改不了"的割裂状态：非创建人用户能看到同组数据，却无法执行任何写操作。

**存在问题：**

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| P1 | 项目管理下标准投放（账户 / 项目 / 单元）与全域投放（账户 / 项目）列表，非创建人用户可查看但操作不可用 | 排班交接后无法及时启停广告、调整预算，错过控损与起量窗口 |
| P2 | 推广管理-标准推广-自动化任务与半自动投放，非创建人用户无法编辑、重试、删除组内其他用户的任务 | 失败任务无法及时重试，任务积压需等创建人上线处理 |
| P3 | 操作权限与查看权限口径不一致，用户无法预判哪个数据能改 | 需逐条试探，认知负担高；排班交接依赖口头协调，效率低 |

## 二、目标与预期收益

**核心目标：操作权限与查看权限对齐——用户对某条数据有查看权限，<b>且用户具备该操作对应的功能权限点</b>，即拥有该数据的操作权限。**（两个条件须同时满足，缺一不可。）

1. 解除"仅创建者可操作"限制，操作权限判定由「当前用户 = 数据创建人」改为「①当前用户对该数据可见，②且用户具备该操作对应的功能权限点」。
2. 覆盖范围：三平台（巨量 / 快手 / 腾讯）下的**项目管理**与**推广管理**（巨量含标准投放 / 全域投放；全域推广含自动化投放 / 素材更新；标准推广含自动化任务 / 半自动投放；快手含项目管理 / 自动化任务·任务列表 / 批量投放；腾讯含项目管理 / 批量投放。详见 3.1）。
3. 所有写操作记录实际操作人，保证代操作行为可追溯、可归责。

**预期收益：**

- **响应效率**：广告异常处理从"等创建人在线"变为"当班即处理"，控损、起量等时效性操作不再被排班阻断。
- **规则统一**：在用户已有功能权限的前提下，可见即可操作，用户无需理解"看得见但点不动"的割裂逻辑。
- **风险可控**：操作人、操作时间、操作对象全量留痕，代操作责任清晰。

## 四、功能需求详述

### 4.1 权限判定规则总原则

| 编号 | 规则 |
| --- | --- |
| R1 | 操作权限判定依据由「当前用户 = 数据创建人」调整为「①当前用户对该数据有查看权限，②且用户具备该操作对应的功能权限点」——两个条件**同时满足**才可操作，任一不满足则维持原状（视为不可操作） |
| R2 | 用户对某条数据无查看权限时，该数据在列表中不可见，自然也不可操作（不放宽数据隔离） |
| R3 | 「可见但不可操作」中间态按原因分类处理：因**创建人不匹配**导致 → 本次放开，入口恢复为可用；因**用户自身角色 / 权限点未配置 / 功能未授权**导致 → 本次不调整，入口维持原状 |
| R4 | 后端接口同步放开创建人校验，改为校验数据范围（可见性），前后端判定规则必须一致 |
| R5 | 本次不新增角色维度的差异化策略：不区分组长 / 组员，统一按可见性 + 功能权限点判定 |

> **生效效果说明**：本规则将「查看」与「操作」对齐——当①数据范围配置允许当前用户可见该数据，②且当前用户已被授予与该写操作对应的功能权限点时，视为该用户拥有操作权限。
>
> **补充边界**：若用户在系统侧未开启对应功能权限点（如未授权「删除」「一键起量」），即使数据范围可见，也按现状保持「可见但不可操作」，不在本次放开范围。

| 编号 | 规则 |
| --- | --- |
| G1 | 高危操作（删除类、批量删除类、一键起量类、关停账户下项目类）保留二次确认；确认文案中明确"该数据由 {创建人} 创建" |
| G2 | 未勾选任何数据时，批量操作按钮保持置灰或点击提示"请先勾选要操作的数据"（维持现状交互） |
| G3 | 跨人混合勾选（自己 + 他人创建的可见数据）一次性全部生效，不做创建人过滤 |
| G4 | 批量执行后，状态列实时更新；部分数据执行失败时按现状返回失败原因，不整体回滚 |
| G5 | 批量修改类弹框（预算 / 出价 / ROI / 时间等）的原始值取所选数据当前值；多选值不一致时展示为空或"多个值"，提交后统一覆盖 |
| G6 | 行级与批量同步放开：同一操作存在批量入口与行级入口时，两者权限结果一致，不做差异对待 |

| --- | --- |

| A2 | 列表「创建人」口径不变，仍为数据创建者；「更新人」= 最近一次实际操作人 |

## 五、交互细节与边界

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| E1 | 列表中不存在无权限数据 | 无权限数据不可见，因此不存在"误勾选越权数据"的场景 |
| E2 | 用户没有任何可见数据 | 列表为空，批量操作栏不展示；行级操作为空 |
| E3 | 多人同时操作同一条数据 | 不做编辑锁，以最后提交结果为准；操作记录保留全部操作痕迹 |
| E4 | 操作他人创建的数据后 | 「创建人」不变，「更新人」变为当前操作人 |
| E5 | 提交时数据已被他人删除 | 校验数据存在性，不存在则提示"数据已不存在"，并刷新列表 |
| E6 | 用户无该页面访问权限 | 仍不可进入页面，页面级权限不因本次调整放开 |
| E7 | 操作组内他人数据被拒 | 不再出现"仅创建人可操作"类报错；若仍报错，视为前端未放开或后端校验未同步，需修复 |
| E8 | 用户自身未开启相关操作权限（非创建人原因） | 维持原状：入口置灰 / 不可点击，不在本次放开范围 |
| E9 | 快手 / 腾讯的页面与操作项命名、数量与巨量存在差异 | 结构差异不影响规则：三平台统一按"可见即可操作 + 功能权限点"放开，具体页面见 3.1 |

## 六、验收标准

### 通用权限规则

☐ 4.2 明细表中列出的每个操作入口，对"非创建人可见数据 + 已授权功能权限点"均处于可用状态，不再隐藏或置灰

☐ 明细表之外的写操作入口（含 tab 下钻后的弹框 / 抽屉 / 失败明细）同样可用

☐ 无可见权限的数据在列表中不出现，无法操作

☐ 后端接口对同一数据的写操作不再返回"仅创建人可操作"类错误（仅对查看权限范围内的数据）

☐ 跨人混合勾选时，批量操作一次性全部生效

☐ 用户自身未开启对应功能权限点时，维持原状（可见但不可操作），不在本次放开范围

### 项目管理（三平台）

☐ 巨量（标准投放：账户 / 项目 / 单元；全域投放：账户 / 项目）各层级列表的批量与行级操作均对非创建人可用

☐ 快手（项目管理：广告计划 / 广告组）各列表的批量与行级操作均对非创建人可用

☐ 腾讯（项目管理：广告 / 创意）各列表的批量与行级操作均对非创建人可用

### 推广管理（三平台）

☐ 巨量（全域推广：自动化投放 / 素材更新；标准推广：自动化任务 / 半自动投放）各列表的批量与行级操作均对非创建人可用

☐ 快手（自动化任务：任务 / 账户 / 广告计划；批量投放）各列表的批量与行级操作均对非创建人可用

☐ 腾讯（批量投放）列表的批量与行级操作均对非创建人可用

☐ tab 下钻后的弹框 / 抽屉 / 失败明细中的写动作同步放开

### 审计与追溯

☐ 代他人操作后，「更新人」更新为实际操作人，「创建人」保持不变

☐ 代他人操作的操作记录按各平台现有规则正常落库；权限调整不引入新的操作记录字段或新展示页

☐ 各平台既有的操作记录筛选 / 追溯能力保持现状不变

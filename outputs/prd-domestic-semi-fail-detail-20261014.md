## 一、背景与现状问题

当前「巨量 → 推广管理 → 标准推广 → 半自动投放」任务列表、账户列表、项目列表中，成功/失败数量已以紧凑形式展示（如「成功0 失败17」）。失败数字以红色呈现，但之前缺少快捷入口查看失败原因，用户需要离开当前列表上下文或进入任务详情页逐条排查。

**存在问题：**

| 编号 | 问题 | 影响 |
| --- | --- | --- |
| P1 | 失败原因查看路径长，需离开列表上下文 | 排查失败耗时、上下文切换成本高 |
| P2 | 无法对失败项目/单元直接批量重试/刷新 | 批量复盘效率低，重复操作多 |

---

## 二、目标与预期收益

1. 任务/账户/项目三个列表的失败数字可点击，直接弹出失败明细弹框，用户无需离开当前列表。
2. 弹框内集中展示失败项目/单元的报错信息，支持批量重试、刷新。
3. 弹框关闭后返回原列表，保持列表上下文。

---

## 三、需求范围

本 PRD 仅聚焦半自动投放任务列表、账户列表、项目列表的失败明细弹框。

- 任务列表「提交项目数」「提交单元数」的失败数字增加点击入口。
- 账户列表「项目数」「单元数」的失败数字增加点击入口。
- 项目列表「单元数」的失败数字增加点击入口。
- 新增「失败明细弹框」，按项目、单元两个层级分别展示失败数据，支持报错信息查看、单条/批量刷新与重试。

## 四、功能需求详述

### 4.1 失败入口展示规则

| 编号 | 规则 |
| --- | --- |
| R1-1 | 任务列表「提交项目数」「提交单元数」下方展示紧凑格式：「成功N 失败M」 |
| R1-2 | 账户列表「项目数」「单元数」下方展示紧凑格式：「成功N 失败M」 |
| R1-3 | 项目列表「单元数」下方展示紧凑格式：「成功N 失败M」 |
| R1-4 | 「失败M」使用红色可点击样式，点击后弹出失败明细弹框 |
| R1-5 | 失败数为 0 时，仅展示「成功N 失败0」，不触发弹框 |

### 4.2 失败明细弹框触发与标题

| 编号 | 规则 |
| --- | --- |
| R2-1 | 点击任务/账户/项目行的「失败M」后，弹出模态弹框 |
| R2-2 | 失败入口与弹框层级对应：任务「提交项目数」→ 项目级；任务「提交单元数」→ 单元级；账户「项目数」→ 项目级；账户「单元数」→ 单元级；项目「单元数」→ 单元级 |
| R2-3 | 弹框标题格式：`失败明细 - {名称} - {层级}`，层级为「项目」或「单元」 |
| R2-4 | 弹框背景遮罩，点击遮罩或关闭按钮可关闭弹框 |

### 4.3 失败明细弹框内容

#### 4.3.1 工具栏

| 编号 | 规则 |
| --- | --- |
| R3-1 | 工具栏左侧展示「已选择 N 个 + 重试」，右侧展示「刷新」按钮 |
| R3-2 | 「已选择 N 个」常显（含 0 个），数量随勾选实时刷新 |
| R3-3 | 「重试」未勾选时点击，提示「请先勾选要重试的数据」 |
| R3-4 | 「刷新」默认刷新弹框内全部失败数据，无需勾选 |

#### 4.3.2 表格字段

| 编号 | 规则 |
| --- | --- |
| R3-5 | 项目级表格列：选择、项目名称/ID、账户名称/ID、报错信息、操作 |
| R3-6 | 单元级表格列：选择、单元名称/ID、所属项目名称/ID、账户名称/ID、报错信息、操作 |
| R3-7 | 名称/ID 两行展示：第一行为名称，第二行为 `ID:xxx` |
| R3-8 | 操作列展示「刷新」「重试」两个行级操作 |

#### 4.3.3 报错信息展示

| 编号 | 规则 |
| --- | --- |
| R3-9 | 报错信息统一以红色文本展示 |
| R3-10 | 后端下发格式支持字符串或结构化对象 `{ code, message, request_id }`，前端仅展示 `message` |
| R3-11 | 报错信息悬浮时展示完整内容（原生 tooltip） |

#### 4.3.4 分页

| 编号 | 规则 |
| --- | --- |
| R3-12 | 弹框底部展示分页：共 N 条、页码、每页条数、跳至第 X 页 |
| R3-13 | 默认每页 10 条，支持切换 10/20/50 条/页 |

### 4.4 批量操作规则

| 编号 | 规则 |
| --- | --- |
| R4-1 | 列表顶部复选框支持全选/取消全选当前页 |
| R4-2 | 行级「刷新」仅刷新当前失败行 |
| R4-3 | 行级「重试」仅重试当前失败行 |
| R4-4 | 工具栏「刷新」作用于弹框内全部失败数据 |
| R4-5 | 工具栏「重试」仅作用于已勾选数据 |

## 五、交互细节与边界

| 编号 | 场景 | 处理 |
| --- | --- | --- |
| E1 | 任务/账户/项目行的失败数为 0 | 不触发弹框；若通过其他入口打开，列表为空 |
| E2 | 关闭弹框 | 关闭后停留在原任务/账户/项目列表位置，列表滚动/选中状态不丢失 |
| E3 | 未勾选点击批量重试 | 提示「请先勾选要重试的数据」 |
| E4 | 报错信息为对象格式 | 前端仅取 `message` 字段展示，`code` 与 `request_id` 仅后端排查使用 |
| E5 | 弹框内切换分页 | 切换后清空当前页勾选状态 |

## 六、验收标准

- [ ] 任务列表「提交项目数」「提交单元数」展示紧凑「成功N 失败M」
- [ ] 账户列表「项目数」「单元数」展示紧凑「成功N 失败M」
- [ ] 账户列表「项目数」失败数字打开项目级弹框，「单元数」失败数字打开单元级弹框
- [ ] 项目列表「单元数」展示紧凑「成功N 失败M」
- [ ] 点击三个列表中的「失败M」均弹出失败明细弹框
- [ ] 弹框标题为「失败明细 - {名称} - {项目/单元}」
- [ ] 项目级弹框表格含：选择、项目名称/ID、账户名称/ID、报错信息、操作
- [ ] 单元级弹框表格含：选择、单元名称/ID、所属项目名称/ID、账户名称/ID、报错信息、操作
- [ ] 报错信息以红色文本展示，内容为后端 `message` 字段
- [ ] 弹框工具栏含：已选择 N 个、重试、刷新
- [ ] 未勾选时点击「重试」给出提示
- [ ] 行级操作含「刷新」「重试」
- [ ] 弹框关闭后停留在原列表，不丢失列表上下文

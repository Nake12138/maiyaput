## 关键术语约定

| 缩写         | 中文                        | 具体含义                                                                 |
| ---------- | ------------------------- | -------------------------------------------------------------------- |
| **US**     | 用户故事（User Story）          | 描述一个完整的需求场景，通常按模块拆分（如 US-001 商务中心列表、US-005 批量分配），每个 US 独立编号并可作为评审单元。 |
| **Desc**   | 描述（Description）           | 简要说明「作为什么角色 → 我想要做什么 → 以便达成什么目的」，是 US 的总览段落。                         |
| **Filter** | 筛选项                       | 列表或弹框顶部的查询条件（输入框、下拉、按钮等），用于过滤可见行。                                    |
| **Fields** | 字段                        | 表格列、表单控件或抽屉详情中需要展示/输入的字段清单。                                          |
| **Source** | 数据来源                      | 字段值从哪个接口/页面/本地缓存获取；如涉及第三方 API，附官方文档链接。                               |
| **Flow**   | 操作流程                      | 从触发入口到结果反馈的完整步骤，按顺序逐条说明用户在页面上的操作路径。                                  |
| **AC**     | 验收标准（Acceptance Criteria） | 用于判断该 US 是否完成的逐条可验证规则，通常是一组短句。                                       |

> 后续模块中提到的 US、Desc、Filter、Fields、Source、Flow、AC 均沿用上表含义。

## 模块 1 · 场景描述（必填）

### ###

在短剧出海广告投放业务中，TikTok 商务中心（BC）、TikTok 账号、账号包是核心资产，需要在投放系统中完整管理。本案例聚焦两个典型需求：

- **TikTok 账号包**：在自动化任务创建/编辑时，支持按「TikTok 账号包」或「手动选择 TikTok 账号」两种模式配置投放身份。
- **商务中心管理**：左侧面板单选 BC，右侧分别管理 BC 用户、TikTok 账号，并支持单个/批量分配账号、已分配账号抽屉批量删除等复杂交互。

产品团队需要在需求评审前快速产出**高保真可交互原型**，并同步产出**结构化的用户故事（US）与需求说明（PRD）**，以便运营、产品、研发三方对齐。

### 1.2 痛点描述

传统流程的痛点：

1. **原型与 PRD 脱节**：PM 用 Axure/墨刀画原型，再单独写 PRD，经常出现字段、列序、交互状态不一致。
2. **术语频繁变更**：商务中心内「用户→成员→TikTok 用户→商务中心用户→BC 用户」多次调整，跨页面/跨文档同步极易遗漏。
3. **公共结构改动易遗漏**：导航、顶栏、版本号、PRD 入口等公共结构在多页面站点需要逐页同步修改，手工操作容易只改其中一部分。
4. **需求验证依赖研发**：静态原型无法自测，很多交互问题要等到前端开发阶段才暴露。

### 1.3 影响范围

- **能力边界**：原流程虽然也是 1 人操作，但产出物不完整，单人通常只能覆盖某一个职能（如 UI 只画页面、UX 只做交互设计、PM 只写文档），跨职能的「PM 写 PRD + UI 画页面 + UX 设计交互」必须多人协作才能完成；Agent 工作流下，**1 人即可同时承担 PM、UI、UX 三个角色的产出**，跨职能沟通次数由 N 次降为 0 次。
- **产出物完整度**：原 1 人产出物往往是「静态原型」或「纯文本 PRD」二选一，评审时经常缺一半；现在单人交付即可覆盖「可运行原型 + 完整 US/PRD + 界面截图 + Git 提交」完整链路，评审即可在线访问。
- **时间**：原流程单个页面的原型 + PRD 产出需 **2–3 天**；Agent 辅助下可压缩到 **0.5–1 天/页**。
- **质量**：9 月 1 日至 18 日共完成 **48 次相关迭代**，US 描述、截图、代码字段始终保持同步。

## 模块 2 · Agent 使用方案（必填）

### 2.1 工具选择与选择原因

| 工具/能力                                                  | 用途                                                        | 选择原因                                                 |
| ------------------------------------------------------ | --------------------------------------------------------- | ---------------------------------------------------- |
| **WorkBuddy 视觉化原型 Skill**（`prototype-design`）          | 根据参考截图输出高保真 HTML 原型，保持项目既定黑白灰主色、顶栏三件套、表格/弹窗/抽屉等组件风格。      | 已内置 58 种设计风格与 Figma 风格默认组件库，可直接复用现有页面 CSS 类名，避免重造组件。 |
| **`proto-to-prd` / `prototype-prd-integration` Skill** | 从原型代码反向梳理页面结构，生成/嵌入用户故事（US）与需求说明；或以浮动入口+侧滑面板形式把 PRD 接入页面。 | 「PR Doc 智能」生成的 PRD 可直接以浮动面板接入页面，评审时随点随看，不离开原型上下文。    |
| **`agent-browser` Skill**                              | 自动打开本地页面、执行 JS 校验、截图对比，验证导航、弹窗、PRD 面板、批量操作等关键路径。          | 替代人工点击验证，可自动化跑完导航矩阵与批量操作，错误时立刻报错并截图。                 |
| **Git + GitHub Pages**                                 | 版本管理与在线预览，提交后自动部署到您的 GitHub Pages 地址（`<请填写>`）。            | 改动后 30–60s 即可在线访问，省去手动部署；评审方无需本地环境即可体验。              |
| **Python 脚本（辅助）**                                      | 按注释锚点 + `<div>` 配对定位，整块替换项目内所有页面的公共结构（如顶栏三件套、CSS 版本号）。      | 静态 HTML 项目无法用组件继承，必须显式批量同步；脚本替代逐个 Edit，降低漏改风险。       |

### 2.2 核心功能

1. **截图即原型**：上传参考图后，Agent 自动输出 HTML/CSS/JS 页面，保持与现有页面一致的导航、顶栏、配色、组件库。
2. **US 与验收标准随页面沉淀**：每个关键模块（列表、弹框、抽屉）都有对应的 US-ID 悬浮按钮，点击展开该模块的完整用户故事与界面截图。
3. **PRD 截图双向同步**：页面交互调整后，用 agent-browser 重新截图并更新 `assets/prd/` 中的 US 配图，确保 PRD 与界面一致。
4. **公共结构批量同步**：导航、顶栏、版本号、公共脚本等改动用 Python 脚本按注释锚点整块替换项目内所有页面，再逐页 grep 校验每页落地一致。
5. **一键提交 GitHub**：改动完成后自动提交、推送，并修复该仓库特有的 `fetch` 不更新远程跟踪引用问题。

### 2.3 使用思路

整体遵循「**先跑通原型 → 再补需求 → 再挂 PRD → 最后验证推送**」四段式：

1. 把参考截图丢给 Agent，让它先还原页面结构与关键交互；
2. 原型确认后，让 Agent 按模块补充用户故事（US）和验收标准（AC）；
3. 将 US/PRD 以浮动按钮+侧滑面板的形式接入页面，方便评审时随时查看；
4. 用 agent-browser 跑关键路径并截图，更新 PRD 配图；
5. 多页面同步检查、提交、推送 GitHub，并处理缓存/远程引用等环境坑。

### 2.4 关键提示词（Prompt）

```text
# 角色
你是海外广告投放系统的产品经理兼前端原型工程师。

# 任务
参考我上传的截图，为【商务中心 / 自动化任务投放身份】绘制高保真 HTML 原型页面。

# 约束
1. 保持项目现有风格：黑白灰主色、顶栏三件套（时区切换器 / 文档下载 / 用户信息下拉）、左侧导航结构。
2. 页面需内嵌 showPage/navUrl 覆盖，保证从其他海外页面跳转到本页路径正确。
3. 关键模块（列表、弹框、抽屉、批量操作）需挂载 US 说明按钮，点击展开对应用户故事。
4. 每个 US 必须包含完整的「描述、筛选项、字段、数据来源、操作流程、验收标准」六段内容（详见上文术语约定）。
5. 完成后用 agent-browser 验证导航矩阵与关键交互，并更新对应 PRD 截图。

# 输出
1. 新增/修改的 HTML/CSS/JS 代码；
2. 本页用户故事清单（US-ID、标题、优先级）；
3. 验证截图与发现的问题清单。
```
